# Hym 自动化架构

## 目标

- 保留当前已经跑通的快手和抖音行为。
- 支持视频、新闻、长时音频及未来未知类型的 App。
- 单设备串行执行，多设备并行运行。
- 允许替换 Airtest/Poco、Appium 或 Android 无障碍实现。
- 关键节点本地可靠记录，后续接入服务端上报。

## 分层

```text
Scheduler
  -> DeviceWorker
      -> AppPlugin
          -> WorkflowBuilder / TaskSet
              -> NavigationController / Step / StateMachine
                  -> VideoContentClassifier / VideoWatchPlanner
                  -> DevicePort
                      -> AirtestPocoDeviceAdapter
                      -> FutureAccessibilityAdapter
```

领域层不能引用 Poco、Airtest、ADB 或具体 OCR 类型。底层返回归一化坐标、标准节点、图像帧和结构化结果。

## 工作流组合

内置任务组件包括签到、余额、奖励广告、视频流、新闻流、评论浏览和音频会话。`ComposedAppPlugin` 只持有 App 规格与工作流构建器，不实现这些业务。现有奖励类 App 可以使用 `DailyWorkflowBuilder` 和 `DailyTaskSet` 组合所需任务；新增内容形态只需增加明确的内容规格类型和任务组件，不需要修改设备运行器或设备后端。

复杂业务保留代码扩展点，不把全部逻辑塞进配置文件。页面、定位策略、重试预算和状态转换优先使用可序列化模型，便于未来迁移到 Kotlin。

每个 App 规格文件同时拥有 `create_plugin()` 入口。常见变化只追加 locator、target 或状态阶段；单项机制不同时，在本 App 文件提供任务或策略并注入 `DailyTaskSet`；整个任务集合、顺序或恢复方式都不同时，直接实现工作流构建器并交给 `create_custom_plugin()`。具体 App 不继承公共业务父类，也不把全部流程塞进配置 DSL。

签到等步骤不是固定点击序列。执行器每次复用当前页面观察，从所有可用阶段中动态匹配动作；某个 App 可以声明直签、打开面板、二次确认、旧版入口等并列分支。明确成功信号优先；缺少成功文案的页面可声明“被动完成信号”，但只有在不存在可执行动作时才生效，避免把加载失败误记为完成。导航和广告同样按当前页面状态推进，不依赖固定返回次数。

多路径任务按“观察当前状态 -> 选择已命中的分支 -> 执行动作 -> 重新观察”推进，规格中的排列只负责同时命中时的优先级，不能假定上一次动作必然进入某个固定页面。尚未出现真实差异的简单任务可以保留短路径；发现新分支后优先在对应 App 增加状态或替换该任务，不提前把所有任务扩展成通用流程语言。

首页恢复、任务页进入、启动弹窗和有限重启由 `NavigationController` 负责。任务组件通过注入的导航函数使用这些能力；是否允许在已经确认首页后重复选择标签、进入任务页前是否选择内容标签，都由 App 导航规格决定，避免刷新或误入沉浸内容流。趣头条一类特殊导航由 App 文件提供包装策略，不需要重写插件。新增页面异常优先扩充 App 的导航规格，只有多个 App 共用同一种恢复行为时才修改导航控制器。

非必要权限拒绝属于跨 App 的导航拦截。普通页面只复用当前 UI 树识别明确的“已安装应用列表”请求；只有前台确实切到 Android 或厂商权限控制器时才额外读取一次原生树。该策略不截图、不 OCR，不自动同意隐私协议，也不为尚未出现的权限类型增加轮询。

视频分类和观看节奏分开处理。`VideoContentClassifier` 只根据 App 规格中的广告、长视频和普通视频标记产出稳定内部类型与证据；`VideoWatchPlanner` 只根据类型和配置决定观看模式、时长分布及是否允许互动。内部逻辑不依赖中文日志文案。新增广告 ID 或关键词只改 App 规格，调整节奏只改配置，上层视频循环保持不变。

分类先复用当前 UI 树；结构没有确认广告时，才对声明了视觉广告标记的 App 补一次纯截图检查，不重复采集 UI 树。视觉广告证据允许覆盖普通内容标记，避免伪装成普通作品的推广内容触发互动。无法明确分类时由 App 配置决定保守观看还是作为疑似广告快速划走，日志分别保存稳定分类码、中文类型、理由和命中标记。

设备内工作流按单个步骤切片执行。每个步骤结束后只做一次轻量概率判断，可切换到其他待办 App 或返回桌面；内容循环还会在单条视频、单篇文章和音频低频检查后暴露安全点。切换时保留内存进度，并把工作流游标写入状态文件用于诊断。进程重启后重新识别入口，不根据旧游标直接点击未知页面。

一个 App 的工作流完整结束后，如果本轮仍有待执行 App，设备先回到桌面按可配置的正态分布休息，再启动下一个 App。临时插空不触发这段休息，最后一个 App 结束后直接进入统一停止应用和锁屏收尾。

## 维护边界

架构优先使用组合和小型任务对象，不建立不断增加钩子方法的超级父类。`ComposedAppPlugin` 只负责组合规格、任务与工作流；App 独有的奖励规则、页面分支和恢复方式留在对应 App 文件或注入的任务/策略中。只有多个 App 已经验证为相同语义的能力，才下沉到公共运行层。

以下数字作为代码评审信号，不作为机械拆分规则：公共运行层的方法原则上不超过 200 行有效逻辑，结构化日志参数不计入；类和生产文件原则上不超过 600 行。App 规格构造和确实需要连续阅读的业务状态机可以例外，但超过边界时必须重新检查是否混入了独立变化原因。

拆分应同时满足至少一个条件：职责可以独立变化、可以独立测试，或状态交接边界清楚。不能只为缩短文件制造一层转发方法，也不能把不同 App 的相似表象抽成带大量条件分支的公共父类。

## 定位策略

每个 App 或页面先声明观察能力，再由少数特殊目标覆盖 UI 树来源，不设全局唯一方案。页面身份组合包名、Activity、必要信号和排除信号，不能只依赖一个可点击目标：

1. 上次成功的策略。
2. UI ID、属性或正则。
3. UI 候选评分。
4. 局部 OCR。
5. 局部图片匹配。
6. 锚点相对位置。
7. 固定坐标兜底。

页面变化后生成一次观察结果，同一轮定位共享截图和 UI 树。正常路径先检查结构信号，结构不足时才补一次 OCR 或图片识别。视频信息流是明确例外：已声明视觉广告标记的 App 会在结构没有确认广告时补一次局部视觉检查，因为广告证据需要能够覆盖表面上的普通内容标记。固定坐标只用于已校准动作，不作为页面身份依据。

低概率弹窗不建立独立轮询。启动边界最多做一次轻量结构观察；导航和内容流程只在主页面状态未命中时，复用当轮观察检查 App 声明的拦截分支。没有可靠标记的首次偶发弹窗允许当前步骤有限失败，重复达到诊断阈值并取得 UI 树或截图后再补规格，不能为一次偶发情况长期增加截图、OCR 或等待。

原生页面优先使用快速树；快速树不可用时才选择系统无障碍树、Activity、局部 OCR 或坐标组合。真机已确认微信和喜马拉雅在当前系统上无法获得有效无障碍树，因此不能假定特殊渲染页面使用无障碍一定更可靠。诊断采集沿用底层默认能力，同时保存警告信息。

## 多设备

每台设备拥有独立 Worker 和设备会话。设备内操作保持串行，不并发调用 Poco；进程锁会阻止主任务与微信独立入口同时操作同一设备。不同设备通过独立进程并行，隔离 Airtest 的全局设备状态。

Worker 保持长连接。默认不做额外健康轮询，设备操作失败时才销毁旧会话并退避重连；需要时可配置低频健康检查。这样兼顾无线调试恢复能力和正常路径性能。单台设备异常退出不影响其他设备。

## 事件与状态

所有执行事件使用版本化 JSON 数据，至少包含事件 ID、设备、App、工作流、步骤、状态、时间和产物引用。链路显式分为 `cycle_id -> app_run_id -> step_run_id`，后续上报后可以还原一次设备轮次中的完整执行顺序。

设备轮次开始时冻结一个业务日期，并传给本轮所有 `AppContext`。签到、余额等每日状态不会因长任务跨过午夜而在同一轮混用两个日期；`app.started` 事件记录该日期，下一轮才使用新的自然日。

截图和 UI 树作为独立产物保存，事件只记录引用。启用 `reporting` 后，`DurableHttpEventSink` 先把事件写入设备独立的 JSONL 队列，再在轮次结束时按批量大小发送到 JDCR Server；失败保留队列，成功后才移除。网络失败后按配置间隔退避，不会在后续每条日志上重复消耗网络超时。服务端使用事件 ID 幂等去重，并将证据文件与结构化元数据分开保存。

上报鉴权与用户查询鉴权分离：设备端写入密钥不能读取数据，KMP App 的用户 Token 不能伪装设备上报。服务端以原始事件为事实源，同时维护轮次、App 运行和步骤聚合表，查询页面不需要每次重放完整事件流。KMP App 只消费稳定的概况、列表、详情和证据接口，不依赖 Python 本地文件布局。

设备控制复用同一鉴权边界，但与事件表分离：每台设备只有一条带截止时间的暂停状态，控制台任务进入持久命令队列。Worker 在安全点低频读取暂停状态，在轮次边界领取任务命令；服务不可用时短超时并退避，不让控制能力反向拖慢业务流程。步骤通过 `TaskScope` 声明签到、余额、广告、主线、准备和收尾语义，远程执行不依赖中文步骤名，也不要求 App 继承公共业务父类。

运行中心的奖励次数采用保守口径：只聚合已经确认的签到、广告完成和领奖事件，不把普通浏览或按钮点击推断为奖励。该聚合不反向驱动设备观察，因此不会为了报表增加截图、OCR、轮询或等待。

正常日志使用中文字段、中文事件名和中文消息，英文事件码只作为稳定筛选键保留。控制台和 JSONL 可分别配置最低级别。以下内容默认只进入调试日志或诊断产物：

- 每次 UI 轮询结果。
- OCR 和图片识别的全部候选。
- 原始 UI 树和触摸坐标。
- 重复等待过程。

手动流程记录器复用同一个设备端口和诊断格式，但不进入无人值守工作流。用户每完成一步后提供操作说明，记录器把操作前后页面、候选定位标记和差异写入增量清单。它用于获取事实并生成新规格，不在日常运行时持续截图或监听触摸。

关键日志包括设备连接与重连、App 开始与结束、工作流及步骤结果、页面状态变化、定位降级、余额与奖励、恢复动作和未处理异常。

余额每天只保存一次成功记录；随机节点未成功时会在流程收尾重试，不会把失败误记为已完成。金币、现金和微信零钱使用“整数最小单位 + 精度”上报，服务端按设备、App、资产和业务日保留最新快照，查询时计算较昨日或较上次变化。支持提现页的 App 每天最多额外采集一次结构化提现快照，只保留可用金额、最低门槛和是否达标，不保存整页 OCR 文本，也不点击确认提现。新闻任务随机选择文章，并按策略随机浏览评论、点赞和阅读到底部，不发布评论。

微信作为独立只读工作流程，在每日时间窗内按有界正态分布抽取一个执行时刻。它只浏览朋友圈、读取零钱和最近账单，不聊天、不点赞、不评论。账单指纹由时间、摘要、方向、金额和币种组成，服务端以“设备 + 指纹”去重。

同一设备、App、工作流和步骤连续失败达到阈值后，才采集截图、UI 树、执行上下文和最近定位轨迹。单次偶发失败只做有限恢复，不增加持续检测负担。

签到等不可重复动作在点击前写入“已执行待确认”检查点，随后更新为“已确认”或“结果不确定”。进程中断或成功标记缺失时，下一轮先核实页面，不直接重复点击。

## 当前实现

- `hym/core`：领域模型、页面规格、配置、端口和结构化事件，不依赖具体自动化框架。
- `hym/runtime`：设备会话、可暂停工作流、导航恢复、独立奖励任务、视频/新闻/音频任务、行为节奏、诊断、广告状态机和多设备调度。
- `hym/locators`：Poco、OCR、图片、锚点与坐标组成的按目标定位链。
- `hym/adapters`：当前 Airtest 输入、Poco/UIAutomator 双树观察和本地存储实现。
- `hym/apps/app_specs`：每个 App 一个独立业务规格文件，集中记录每日流程、限制、任务分支和匹配标记。
- `hym/apps`：公共 App 规格模型、组合式插件、默认每日工作流构建器和注册表。
- `hym/testing`：可注入的设备、时钟、随机源和存储替身。

原有四个 App 已完成组合式架构真机复验：快手、抖音完成视频和奖励流程；趣头条完成多篇新闻；喜马拉雅完成可中断恢复的长时音频会话。

新增五个 App 的真机适配继续保持同一边界：番茄小说使用 App 内横向阅读任务，今日头条复用新闻任务，番茄畅听复用音频会话，百度和悟空复用视频任务。复盘后只把两项已经被多个 App 证明相同的能力收进组合层：任务页进入前可不选择内容标签，以及所有业务结束后的清理步骤。任务页弹窗、特殊签到、宝箱、红包和页面标记仍留在对应 App 文件；没有修改设备端口、定位链、会话或内容执行器。以后若只是某个 App 路径变化，仍应只改该 App 文件和配置。

## 扩展边界

替换 Airtest/Poco 时实现 `DevicePort` 与 `DeviceFactoryPort`，上层工作流和 App 规格保持不变。未来 Android 无障碍版本可以沿用相同的页面目标、步骤结果、事件协议和状态机设计，再按 Kotlin 类型重建端口实现。

新增 App 可以复用全部默认任务、替换 `DailyTaskSet` 中某一个任务，或提供完全独立的工作流。只在真实流程相同时复用组件，不要求不同类型 App 套用统一签到或奖励模型。定位策略属于具体页面和目标，不要求整个 App 使用同一种技术。
